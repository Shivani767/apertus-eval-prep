# Colab real-model evidence

Curated, committed artifacts from real open-weight model runs on free Colab GPU
(`LOCAL_REAL_MODEL` evidence). One directory per model, named after the Hugging Face
repository.

| model | runs | summary |
|---|---|---|
| `Qwen/Qwen2.5-3B-Instruct` | 11 (10 real-model + 1 mock smoke) | [summary.md](Qwen2.5-3B-Instruct/summary.md) |
| `HuggingFaceTB/SmolLM2-1.7B-Instruct` | 11 (10 real-model + 1 mock smoke) | [summary.md](SmolLM2-1.7B-Instruct/summary.md) |

Both runs share the same dataset, task, prompt and metric identities, so their quality
means are directly comparable; the model id and revision are the intended difference.

## Layout (per model)

`<Model>/` is the notebook's exported run tree, unchanged: `local_baseline/`,
`local_variance/`, `local_rag_agent/`, `local_safety/`, `mock_smoke/`, `study/`,
`configs/`, `comparison_points.json`, `selection.json`, `review_package.jsonl`.
Each run directory keeps the platform's immutable artifacts (`manifest.json`,
`config.resolved.yaml`, `metrics.json`, `confidence_intervals.json`, `gate_report.json`,
`failures.jsonl`, `failure_fingerprint.json`, `scored_examples.jsonl`, `raw_outputs.jsonl`,
`report.md`, `report.html`).

Two derived files are added on top:

- `summary.md` / `summary.json` — generated by `scripts/summarise_real_model_results.py`.
  Do not hand-edit them; a test regenerates the summary and fails if the committed copy
  differs.

## Interpretation rules

- Only `LOCAL_REAL_MODEL` runs support statements about model quality. `mock_smoke/` is
  framework validation, not evidence.
- Two runs are comparable only when `evidence_mode`, `dataset_hash`, `task_hash`,
  `prompt_hash`, `prompt_version` and `metric_definition_version` match. `model_id` and
  its revision are expected to differ when the comparison spans models.
- Latency is client-side wall-clock time on ephemeral Colab hardware; it is not
  production serving latency.
- A `BLOCKED_*` gate is an engineering policy aid, not production approval. Read the
  "Warnings" section of a model's `summary.md` before quoting any number from it.
- Every model directory records the revision it was run against. A revision of `main` is
  not a pinned commit; the run cannot be reproduced exactly from that tree alone.

## Adding a model

1. Generate its notebook: `python3 scripts/build_real_model_notebooks.py` (registry in
   `scripts/build_real_model_notebooks.py`).
2. Run `notebooks/real_model_<slug>.ipynb` in its own Colab account; section 6 exports the
   zip.
3. Extract the zip into `results/colab_real_model/<HF model name>/`.
4. `python3 scripts/summarise_real_model_results.py results/colab_real_model/<HF model name>`
5. Rebuild the reports so every model shares one style (rendering only, no re-inference):
   `python3 scripts/regenerate_colab_reports.py results/colab_real_model/<HF model name>`
6. Commit the run tree plus the generated `summary.json` and `summary.md`.
